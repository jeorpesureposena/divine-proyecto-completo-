  DESCRIPCIÓN
  -----------
  Este manifiesto documenta el mapeo técnico entre las rutas URL del proyecto
  DivinePark (implementado en Django) y sus equivalentes en la especificación
  Java Servlet (javax.servlet.http.HttpServlet).

  Principio Arquitectónico:
    El URLconf Dispatcher de Django (urls.py) cumple la misma función que el
    archivo web.xml de un Servlet Container (Apache Tomcat / JBoss), resolviendo
    la ruta de la petición HTTP y despachando la ejecución al controlador
    correspondiente (Servlet de Servicio).

================================================================================
  MAPEO DE COMPONENTES ARQUITECTÓNICOS (Django ↔ Java EE)
================================================================================

  COMPONENTE JAVA EE                  | COMPONENTE DJANGO / DRF
  ----------------------------------- | -----------------------------------------------
  javax.servlet.http.HttpServlet      | rest_framework.views.APIView / @api_view
  javax.servlet.http.HttpServletReq.  | rest_framework.request.Request (request)
  javax.servlet.http.HttpServletResp. | rest_framework.response.Response
  web.xml <servlet-mapping>           | urls.py (URLconf + DefaultRouter)
  doGet(req, resp)                    | def get(self, request) / @api_view(['GET'])
  doPost(req, resp)                   | def post(self, request) / @api_view(['POST'])
  doPut(req, resp)                    | def put(self, request) / @api_view(['PUT'])
  doDelete(req, resp)                 | def delete(self, request) / @api_view(['DELETE'])
  req.getParameter("x")              | request.data.get('x') / request.query_params['x']
  req.getUserPrincipal()             | request.user (JWT-authenticated)
  HttpSession / session.setAttribute  | JWT Token (refresh + access) — stateless
  session.invalidate()               | RefreshToken.blacklist()
  resp.setStatus(200)                 | Response(status=status.HTTP_200_OK)
  resp.getWriter().write(json)        | Response(data_dict)
  javax.persistence.EntityManager    | Django ORM (models.py — QuerySet API)
  @WebServlet("/path")               | path('url/', view, name='name') en urls.py
  ServletContext                      | Django settings.py + AppConfig
  FilterChain                         | Django Middleware (settings.MIDDLEWARE)
  init() / destroy()                  | AppConfig.ready() / signal handlers

================================================================================
  NOTA TÉCNICA SOBRE EL CICLO DE VIDA
================================================================================

  En Java Servlets:
    1. El contenedor (Tomcat) instancia el Servlet (init).
    2. Por cada petición HTTP crea objetos HttpServletRequest/Response.
    3. Llama a service() → que despacha a doGet/doPost según el método HTTP.
    4. Al apagar el servidor llama destroy().

  En Django REST Framework (equivalente):
    1. El servidor WSGI (Gunicorn/uWSGI) carga la aplicación Django (init).
    2. Por cada petición HTTP crea un objeto Request (wrapping de WSGIRequest).
    3. El URLconf despacha al ViewSet/view correspondiente.
    4. Se ejecuta el método correspondiente al verbo HTTP (get/post/put/delete).
    5. Se retorna un objeto Response serializado en JSON.

  Este ciclo es FUNCIONALMENTE IDÉNTICO al ciclo de vida de un Servlet Java.
